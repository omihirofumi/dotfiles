# 学習デッキの作り方

## 目的

デッキはプレゼンであり、目的は「わかってもらうこと」。情報を並べるのではなく、構造が一目で伝わることを最優先にする。装飾でごちゃごちゃさせるのは逆効果。

## 作業の前提

- 題材（記事・本の章・ドキュメント）は、要約や抜粋で済ませず、全文を読んでから構成する。
- 出力は単一のHTML Artifact（外部ライブラリ依存なしの単一HTMLファイル）。1スライドずつ表示するページャー形式にする。

## スライドの構成

- 1スライド = 1メッセージ。言いたいことが2つあるなら、スライドを分ける。
- 各スライドの要素:
  - タイトル
  - 図（スライドの中心）
  - 「このスライドの結論」を1行
  - スピーカーノート形式の詳しい説明（スライドの隣、狭い画面では下に表示）
  - 必要に応じて「コードで見る」ブロック
- 具体例（コード例）を必ず入れる。抽象的な説明だけで終わらせない。
- 最後のページに以下を付ける:
  - 要点まとめ
  - 想起フック（自問＋模範解答、開閉式）
  - FAQ（想定質問と回答、3〜6問）

## 図のルール（最重要）

- 図は本物の図解にする。箱・矢印・フロー・階層・境界といった空間構造で「関係」を描くこと（SVGで描く）。
- 色や枠で修飾しただけのテキストブロックは図ではない。
- 装飾的なイラスト（情景描写やアイコンの寄せ集め）は禁止。要素は最小限に絞り、余白を広めに取る。
- 図の中のラベルは短く。詳しい説明はノートに書く。
- コントラスト: 濃い色の面の上には白など明るい文字を使う。CSSがSVGの文字色（`fill`）を上書きして読めなくなる事故に注意し、濃い面上の文字はクラス等で明示的に色を指定する。

## レイアウトのルール

- ページャー必須: 前へ/次へボタン、進捗バー、カウンタ（`n / N`）、目次からのジャンプ、矢印キー・スワイプ対応。
- 全スライドを縦に積むスクロール形式にしない。
- スマホ幅（390px程度）で右端が切れないこと。グリッドには `minmax(0, 1fr)` を使うなど、はみ出しを防ぐ。
- コードブロックは横にはみ出さないよう、行を折り返すか短くする。

## 出力（HTML Artifact）

- `Artifact` ツールが使える環境では、`Artifact`（`action: "quickstart"`, `intent: "other"`）でページ規約を確認し、単一の `.html` ファイルを作成して HTML Artifact として公開し、リンクを返す。
  - 同じセッション内で同じデッキを更新する場合は、同じファイルパスで再公開してリンクを維持する。
  - 機密情報を含む場合は、ファイル作成後に公開してよいか確認する。
- `Artifact` ツールがない環境では、単一の `.html` ファイルとして出力する。

## 仕上げの自己チェック

- [ ] 各スライド、図だけ見て関係が伝わるか
- [ ] 1スライド1メッセージになっているか
- [ ] 具体例（コード）が入っているか
- [ ] 濃い面の上の文字が読めるか（コントラスト）
- [ ] スマホ幅で切れていないか
- [ ] 要点まとめ・想起フック・FAQが付いているか
